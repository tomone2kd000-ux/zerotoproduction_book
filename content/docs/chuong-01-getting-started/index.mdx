# Chương 1: Bắt Đầu & Thiết Lập Toolchain

Một ngôn ngữ lập trình không chỉ bao gồm cú pháp hay ngữ nghĩa trừu tượng: **hệ thống công cụ (Tooling) chính là yếu tố then chốt quyết định trực tiếp đến trải nghiệm thực tế của kỹ sư khi làm việc với ngôn ngữ đó.**

Điều tương tự cũng xuất hiện ở nhiều công nghệ khác (ví dụ như các RPC framework như gRPC hay Apache Avro), nơi trải nghiệm công cụ hỗ trợ thường tạo ra tác động mang tính sống còn đối với sự phổ biến (hoặc lụi tàn) của chính công nghệ ấy.

Chính vì vậy, công cụ phát triển phải luôn được coi là **công dân hạng nhất (first-class concern)** trong cả quá trình thiết kế lẫn giảng dạy một ngôn ngữ lập trình.

<Callout type="info">
  Cộng đồng Rust đã đặt vấn đề công cụ lên hàng ưu tiên số một ngay từ những ngày đầu sơ khai, và điều đó được thể hiện rõ ràng qua hệ sinh thái công cụ vô cùng sắc bén mà chúng ta sẽ cùng thiết lập trong chương này.
</Callout>

## I. Bản Đồ Công Cụ Trong Chương 1

Trước khi bắt tay vào viết logic cho dịch vụ backend, chúng ta sẽ cùng nhau xây dựng một nền móng vững chắc với một môi trường làm việc chuẩn mực:

```text
                  HỘP CÔNG CỤ CHUẨN RUST SENIOR DEVELOPER
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  1. Quản lý Toolchain (rustup)                                          │
│     ├── Trình biên dịch: rustc (kênh stable)                            │
│     ├── Trình quản lý dự án & gói thư viện: cargo                       │
│     └── Quản lý mục tiêu biên dịch: target platforms (Tier 1-3)         │
│                                                                         │
│  2. Môi trường Lập trình Tương tác (IDE Setup)                          │
│     ├── rust-analyzer (LSP cho VS Code, Neovim, v.v.)                   │
│     └── IntelliJ Rust / RustRover (JetBrains)                           │
│                                                                         │
│  3. Vòng Lặp Phát Triển Nhanh (Inner Development Loop)                  │
│     ├── Tăng tốc khâu liên kết mã máy (Linking): lld, mold              │
│     └── Theo dõi thay đổi & biên dịch tự động: cargo-watch              │
│                                                                         │
│  4. Đường Ống Tích Hợp Liên Tục (CI Pipeline Checks)                    │
│     ├── Kiểm thử tự động: cargo test                                    │
│     ├── Đo độ bao phủ mã nguồn: cargo-tarpaulin                         │
│     ├── Phân tích tĩnh & bắt lỗi tiềm ẩn: clippy                        │
│     ├── Chuẩn hóa định dạng mã nguồn: rustfmt                           │
│     └── Kiểm toán lỗ hổng bảo mật thư viện: cargo-audit                 │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## II. Các Mục Tiêu Cần Đạt Được

1. **Hiểu rõ cơ chế Toolchain**: Phân biệt giữa Target Platform, Release Channels (`stable`, `beta`, `nightly`) và cách quản lý phiên bản qua `rustup`.
2. **Khởi tạo dự án `zero2prod`**: Làm chủ công cụ `cargo` và thiết lập cấu trúc mã nguồn ban đầu có tích hợp kiểm soát phiên bản Git.
3. **Cấu hình IDE hỗ trợ chuyên sâu**: Thiết lập tính năng tô màu cú pháp, nhảy định nghĩa hàm (*code navigation*) và gợi ý code thông minh (*code completion*) để hỗ trợ phong cách lập trình khám phá (*exploratory programming*).
4. **Cắt giảm thời gian biên dịch**: Tối ưu khâu liên kết (*linking phase*) với `lld` và thiết lập `cargo-watch` để vòng lặp chỉnh sửa - phản hồi diễn ra tức thì.
5. **Dựng sẵn Pipeline CI hoàn chỉnh**: Khép kín quy trình kiểm tra chất lượng trước khi sáp nhập mã nguồn vào nhánh `main`.
