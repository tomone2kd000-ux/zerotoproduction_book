# Deploy Lên DigitalOcean Apps Platform & Quản Lý Môi Trường

Chúng ta đã có một Docker image tối ưu chỉ nặng 125 MB, hỗ trợ offline build với `sqlx` và được tăng tốc biên dịch thần tốc nhờ `cargo-chef`. Bây giờ là thời khắc quyết định: **Đưa ứng dụng lên nền tảng đám mây DigitalOcean App Platform!**

---

## 5.4.1. Thiết Lập Công Cụ & doctl CLI

Đầu tiên, bạn cần đăng ký một tài khoản trên [DigitalOcean](https://cloud.digitalocean.com/registrations/new) và cài đặt công cụ dòng lệnh [`doctl`](https://www.digitalocean.com/docs/apis-clis/doctl/how-to/install/).

Sau khi cài đặt xong, tạo một API token từ trang quản trị DigitalOcean và xác thực trên máy cục bộ:

```bash
doctl auth init
```

Nhập token bí mật của bạn khi được yêu cầu.

<Callout type="info">
  **Mẹo tiết kiệm chi phí**: Duy trì ứng dụng và cụm PostgreSQL trên DigitalOcean tốn khoảng 20 USD/tháng. Khi học tập, bạn có thể xóa app (`doctl apps delete <ID>`) vào cuối mỗi buổi học. Chi phí thực tế chỉ tính theo giờ sử dụng, bạn sẽ chỉ tốn khoảng 0.20 - 1.00 USD cho toàn bộ quá trình thực hành chương này.
</Callout>

## 5.4.2. Khai Báo Đặc Tả Ứng Dụng (App Specification)

DigitalOcean App Platform sử dụng một file khai báo dạng declarative để mô tả toàn bộ cấu hình triển khai của ứng dụng — gọi là **App Spec**.

Tạo file `spec.yaml` tại thư mục gốc của dự án:

```yaml
#! spec.yaml
name: zero2prod
# Frankfurt (Đức - Châu Âu), xem bảng mã vùng tại tài liệu DigitalOcean
region: fra
services:
  - name: zero2prod
    dockerfile_path: Dockerfile
    source_dir: .
    github:
      branch: main
      # Tự động kích hoạt deploy mỗi khi push commit mới lên main!
      deploy_on_push: true
      # Thay bằng thông tin repo GitHub của bạn (vd: LukeMathWalker/zero-to-production)
      repo: <YOUR_GITHUB_USERNAME>/<YOUR_REPOSITORY_NAME>
    # Probe kiểm tra sức khỏe của ứng dụng
    health_check:
      http_path: /health_check
    http_port: 8000
    instance_count: 1
    instance_size_slug: basic-xxs
    routes:
      - path: /
```

Khởi tạo ứng dụng trên DigitalOcean bằng `doctl`:

```bash
doctl apps create --spec spec.yaml
```

Nếu chưa cấp quyền cho DigitalOcean truy cập kho lưu trữ GitHub của bạn, hãy làm theo hướng dẫn trên màn hình để liên kết tài khoản. 

Sau khi lệnh hoàn tất, bạn có thể kiểm tra danh sách app:

```bash
doctl apps list
```

Trên dashboard của DigitalOcean, bạn sẽ thấy tiến trình build Docker image tự động bắt đầu. Khi build hoàn tất, hệ thống sẽ cấp phát một tên miền công khai dạng:

```text
https://zero2prod-aaaaa.ondigitalocean.app
```

DigitalOcean tự động cấu hình chứng chỉ bảo mật HTTPS (SSL/TLS termination) và điều hướng truy vấn vào container của bạn. Hãy thử gửi request:

```bash
curl -v https://zero2prod-aaaaa.ondigitalocean.app/health_check
```

Phản hồi trả về `HTTP/1.1 200 OK`! Endpoint health check đầu tiên của chúng ta đã chính thức chạy trên toàn cầu.

Tuy nhiên, endpoint `POST /subscriptions` vẫn thất bại vì ứng dụng trên cloud chưa có cơ sở dữ liệu PostgreSQL.

## 5.4.3. Inject Secrets Bằng Biến Môi Trường

Chuỗi kết nối cơ sở dữ liệu (connection string) chứa các thông tin nhạy cảm (mật khẩu người dùng root). **Tuyệt đối không bao giờ được commit mật khẩu vào Git!**

Giải pháp chuẩn mực là nạp các bí mật này thông qua **Biến môi trường (Environment Variables)** tại thời điểm runtime.

Chúng ta nâng cấp hàm `get_configuration` trong `src/configuration.rs` để cho phép ghi đè bất kỳ giá trị cấu hình nào thông qua biến môi trường có tiền tố `APP_` và dấu phân cách lồng nhau `__`:

```rust
//! src/configuration.rs
// [...]

pub fn get_configuration() -> Result<Settings, config::ConfigError> {
    let base_path = std::env::current_dir().expect("Không thể xác định thư mục hiện tại.");
    let configuration_directory = base_path.join("configuration");

    let environment: Environment = std::env::var("APP_ENVIRONMENT")
        .unwrap_or_else(|_| "local".into())
        .try_into()
        .expect("Không thể phân tích APP_ENVIRONMENT.");
    let environment_filename = format!("{}.yaml", environment.as_str());

    let settings = config::Config::builder()
        .add_source(config::File::from(configuration_directory.join("base.yaml")))
        .add_source(config::File::from(configuration_directory.join(environment_filename)))
        // Ghi đè bằng biến môi trường (Ví dụ: `APP_APPLICATION__PORT=5001`)
        .add_source(
            config::Environment::with_prefix("APP")
                .prefix_separator("_")
                .separator("__")
        )
        .build()?;

    settings.try_deserialize::<Settings>()
}
```

### Xử Lý Ép Kiểu Số Với `serde-aux`
Biến môi trường luôn được hệ điều hành cung cấp dưới dạng chuỗi văn bản (`String`). Để thư viện `config` không bị lỗi khi deserialize một chuỗi ký tự thành kiểu số nguyên `u16` cho cổng `port`, ta dùng crate [`serde-aux`](https://crates.io/crates/serde-aux):

```toml
#! Cargo.toml
[dependencies]
serde-aux = "4"
```

Áp dụng attribute cho các struct:

```rust
//! src/configuration.rs
use serde_aux::field_attributes::deserialize_number_from_string;

#[derive(serde::Deserialize)]
pub struct ApplicationSettings {
    #[serde(deserialize_with = "deserialize_number_from_string")]
    pub port: u16,
    pub host: String,
}

#[derive(serde::Deserialize)]
pub struct DatabaseSettings {
    #[serde(deserialize_with = "deserialize_number_from_string")]
    pub port: u16,
    // [...]
}
```

## 5.4.4. Kết Nối Managed PostgreSQL Qua SSL

Chuỗi kết nối của cụm cơ sở dữ liệu trên DigitalOcean có định dạng:

```text
postgresql://newsletter:<PASSWORD>@<HOST>:<PORT>/newsletter?sslmode=require
```

Trên môi trường production, toàn bộ kết nối giữa ứng dụng và máy chủ CSDL bắt buộc phải được mã hóa truyền tải qua **SSL/TLS (`sslmode=require`)**.

Hãy nâng cấp struct `DatabaseSettings` để trả về `PgConnectOptions` của SQLx thay vì ghép chuỗi thủ công, đồng thời thêm tùy chọn `require_ssl: bool`:

```rust
//! src/configuration.rs
use secrecy::ExposeSecret;
use sqlx::postgres::{PgConnectOptions, PgSslMode};
use sqlx::ConnectOptions;

#[derive(serde::Deserialize)]
pub struct DatabaseSettings {
    pub username: String,
    pub password: Secret<String>,
    #[serde(deserialize_with = "deserialize_number_from_string")]
    pub port: u16,
    pub host: String,
    pub database_name: String,
    pub require_ssl: bool,
}

impl DatabaseSettings {
    pub fn without_db(&self) -> PgConnectOptions {
        let ssl_mode = if self.require_ssl {
            PgSslMode::Require
        } else {
            PgSslMode::Prefer
        };

        PgConnectOptions::new()
            .host(&self.host)
            .username(&self.username)
            .password(self.password.expose_secret())
            .port(self.port)
            .ssl_mode(ssl_mode)
    }

    pub fn with_db(&self) -> PgConnectOptions {
        let mut options = self.without_db().database(&self.database_name);
        // Hạ mức log các câu query SQL của SQLx xuống TRACE để tránh làm bẩn hệ thống log
        options.log_statements(tracing_log::log::LevelFilter::Trace);
        options
    }
}
```

Cập nhật file cấu hình YAML:
- `configuration/local.yaml`: Thêm `database: require_ssl: false`.
- `configuration/production.yaml`: Thêm `database: require_ssl: true`.

Trong `src/main.rs`, ta chuyển sang dùng `connect_lazy_with`:

```rust
//! src/main.rs
use sqlx::postgres::PgPoolOptions;

#[tokio::main]
async fn main() -> Result<(), std::io::Error> {
    // [...]
    let connection_pool = PgPoolOptions::new()
        .connect_lazy_with(configuration.database.with_db());

    // [...]
}
```

## 5.4.5. Khai Báo Biến Môi Trường Trong App Spec (`spec.yaml`)

Thêm cấu hình cụm cơ sở dữ liệu `databases` và khối biến môi trường `envs` vào file `spec.yaml`:

```yaml
#! spec.yaml
name: zero2prod
region: fra
services:
  - name: zero2prod
    dockerfile_path: Dockerfile
    source_dir: .
    github:
      branch: main
      deploy_on_push: true
      repo: <YOUR_GITHUB_USERNAME>/<YOUR_REPOSITORY_NAME>
    health_check:
      http_path: /health_check
    http_port: 8000
    instance_count: 1
    instance_size_slug: basic-xxs
    routes:
      - path: /
    envs:
      - key: APP_DATABASE__USERNAME
        scope: RUN_TIME
        value: ${newsletter.USERNAME}
      - key: APP_DATABASE__PASSWORD
        scope: RUN_TIME
        value: ${newsletter.PASSWORD}
      - key: APP_DATABASE__HOST
        scope: RUN_TIME
        value: ${newsletter.HOSTNAME}
      - key: APP_DATABASE__PORT
        scope: RUN_TIME
        value: ${newsletter.PORT}
      - key: APP_DATABASE__DATABASE_NAME
        scope: RUN_TIME
        value: ${newsletter.DATABASE}
databases:
  - engine: PG
    name: newsletter
    num_nodes: 1
    size: db-s-dev-database
    version: "12"
```

Cú pháp `${newsletter.XYZ}` cho phép DigitalOcean tự động nội suy thông tin kết nối từ cụm database vừa tạo vào biến môi trường của container khi khởi chạy (`scope: RUN_TIME`).

## 5.4.6. Đợt Đẩy Cuối Cùng (One Last Push)

Bây giờ ta áp dụng bản cập nhật đặc tả lên DigitalOcean:

```bash
# Lấy app-id từ lệnh doctl apps list
doctl apps update <YOUR-APP-ID> --spec=spec.yaml
```

Đồng thời commit toàn bộ các thay đổi (`configuration/`, `spec.yaml`, `Dockerfile`, `.sqlx/`) và đẩy lên GitHub:

```bash
git add .
git commit -m "Configure production database and continuous deployment"
git push origin main
```

### Chạy Migration Cơ Sở Dữ Liệu
Trước khi endpoint có thể lưu dữ liệu, ta cần chạy migration để tạo bảng `subscribers` trên cơ sở dữ liệu PostgreSQL của DigitalOcean. Lấy chuỗi kết nối từ tab **Database** trên dashboard và chạy:

```bash
DATABASE_URL="<DIGITAL_OCEAN_CONNECTION_STRING>" sqlx migrate run
```
